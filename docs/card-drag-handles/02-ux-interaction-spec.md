# 卡片拖拽手柄交互规格

## 文档关系

本规格落实[产品需求](01-product-requirements.md)中的验收行为。实现约束见[技术设计](03-technical-design.md)，实施与验证步骤见[实施计划](04-implementation-plan.md)。

## UX-CDH-001：入口与状态

标题栏不再提供排序按钮。排序入口始终位于符合条件的卡片内部，用户不需要先切换模式。

系统在每次网格数据刷新后，按下列规则决定手柄可见性和可操作性：

1. 搜索关键词必须为空。
2. 当前视图必须是全局视图，或 ID 大于 0 的真实分组。
3. 当前网格必须至少有 2 张卡片。

三个条件均满足时，每张卡片显示手柄。任一条件不满足时，所有手柄隐藏，网格不能重排。

## UX-CDH-002：允许与禁止的视图

| 当前视图 | 搜索关键词 | 卡片数 | 手柄 | 拖拽排序 |
|---|---:|---:|---|---|
| 全局视图 | 空 | 至少 2 | 显示 | 允许 |
| 正数真实分组 | 空 | 至少 2 | 显示 | 允许 |
| 全局视图或正数真实分组 | 非空 | 任意 | 隐藏 | 禁止 |
| 收藏夹 `-2` | 任意 | 任意 | 隐藏 | 禁止 |
| 最近使用 `-3` | 任意 | 任意 | 隐藏 | 禁止 |
| 未分类 `-4` | 任意 | 任意 | 隐藏 | 禁止 |
| 任意视图 | 任意 | 少于 2 | 隐藏 | 禁止 |

搜索输入、清空搜索、切换分组、导入、删除、分享后刷新或同步后刷新，都必须重新计算该状态。

## UX-CDH-003：卡片布局与无障碍

手柄位于卡片左上区域。右上区域保留给 GIF、WebP 或隐写导入角标，卡片底部保留给名称遮罩。手柄的实际触摸区域约为 48dp，视觉图形可以小于触摸区域。

手柄需要使用本地化内容描述，例如“拖动排序”。图片内容描述继续为空，避免重复朗读。手柄获得辅助功能焦点时，读屏应能识别它是用于调整当前卡片顺序的控件。

## UX-CDH-004：手势分工

| 操作区域与手势 | 结果 |
|---|---|
| 手柄按下后拖动 | 开始拖拽并在网格内换位。 |
| 卡片根视图轻触 | 保持现有分享行为，同时记录最近使用。 |
| 卡片根视图长按 | 保持现有上下文菜单。 |
| 不可排序视图中的任意长按 | 只执行根卡片的上下文菜单，不开始拖拽。 |

手柄是拖拽的唯一入口。用户长按卡片其他位置时不得开始拖拽，因此长按菜单不再因排序状态被关闭。

## UX-CDH-005：排序反馈与完成

拖拽期间，卡片跟随现有 `ItemTouchHelper` 换位反馈。用户释放后，界面保留最终卡片顺序。无需新增排序模式提示、Toast 或确认弹窗。

在全局视图中，完成后的顺序代表全局表情顺序。在正数真实分组中，完成后的顺序只代表该分组成员顺序。

## UX-CDH-006：验证要点

人工验证必须覆盖：

- 全局视图与正数真实分组中的手柄可见、拖动和重新加载后的顺序。
- 搜索和三个虚拟分组中手柄隐藏。
- 只有一张卡片时手柄隐藏。
- 可排序视图中，手柄外点击能打开分享，长按根卡片能打开原菜单。
- 角标、名称和手柄在普通卡片、动图卡片及隐写导入卡片上不互相遮挡。
- TalkBack 或等效辅助功能读取手柄的本地化描述并可聚焦其触摸区域。

这些检查依赖可运行的 Android 模拟器或真实设备，尚未执行。对应需求和技术追踪见[产品需求](01-product-requirements.md#追踪)与[技术设计](03-technical-design.md#追踪)。
